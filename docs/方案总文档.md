## P0：底盘用例静态风险审查

- 状态：P0/P1 已完成（2026-07-28）；Allure P2 已完成，Excel ID/标题迁移待后续单独处理。
- P0：`chassis_auto_connect` 默认值为 `False`，与会话技能基线冲突，可能使启用硬件门控后所有底盘用例因 fixture 未启用而跳过；制动查询 API 在当前 SDK 中返回 `bool`，三个底盘断言点却显式拒绝 `bool`；多个执行类用例只断言返回值非空，`plain_return=True` 下 SDK 失败返回的非空 `CommandResult` 可能被误判为成功。
- P1：下电、轮毂使能和 LED 颜色用例没有恢复真实原状态；升降标定未标记 `motion` 且无完成等待；轮毂控制/停止只按 Excel 时长睡眠，未确认停止状态。
- P2：37 个底盘文件使用英文 Allure feature、38 个使用英文 story；11 个 Excel sheet 的用例 ID 不是连续纯数字，标题也重复 ID/API。
- 验证：`pytest testcases/chassis --collect-only -q` 收集 55 条用例；`python -m compileall -q testcases/chassis` 通过。
- 已实施：底盘默认自动连接、轮毂制动 `bool` 契约、执行接口失败结果判定、电源状态恢复与超时等待、升降标定的 `motion` 门控和完成等待；轮毂/升降运动及不可读取原状态的 LED/轮毂使能测试均增加人工确认门控。
- 已实施：全部底盘 Allure feature/story 改为中文功能描述并保留 API 标识符；未改动 Excel 的历史 ID 与标题，避免破坏既有报告关联。
