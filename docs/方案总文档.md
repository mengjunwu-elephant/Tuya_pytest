## P0：坐标 Jog 结束态按实机结果调整

- 状态：已完成（2026-07-31）
- 问题：`upper_jog_coord` 统一期望 `32`“坐标无解”，与实机不一致；部分轴返回业务值 `0`，部分返回 `33`“直线运动无相邻解”。
- 方案：按实机逐条写入 Excel 预期与 title；测试按 `expect_data` 分支——有业务期望时只断言返回值，否则断言失败 `CommandResult` 的状态码与消息；失败路径仍回读停止坐标并回零。
- 边界：仍不将坐标软限位用作 Jog 终点；unsupported / exception 用例不变。
- 验证：静态编译与用例收集；不在本次改动中跑真机复验。

## P0：刷新模式运动默认异步全量覆盖

- 状态：已完成（2026-07-29）
- 问题：此前只有 `send_upper_angle` 在切换刷新模式后显式设置 SDK 默认异步状态，其他刷新模式运动仍可能因“无到位反馈”被拒绝。
- 方案：在 `send_upper_coord`、`send_upper_angles`、`send_upper_coords` 的模式回读后调用并断言 `set_upper_motion_async(fresh_mode == 1)`；在关节/坐标 Jog 的刷新模式不支持验证中，切换刷新模式后显式调用 `set_upper_motion_async(True)`。
- 清理：发送用例恢复运动前的默认异步状态；Jog 不支持验证在回零前恢复双臂插补模式和默认同步状态。
- 验证：静态编译、相关模块收集和差异检查；不运行真机。

## P0：公共回零改为零位关节运动

- 状态：已完成（2026-07-29）
- 原因：SDK `upper_go_zero()` 的专用回零路径耗时较长，影响每条需恢复零位的运动用例。
- 方案：保留 `TuyaRobotBase.go_zero()`、`go_arm_zero()` 的调用入口、返回值校验和超时等待；其内部改为用 `UPPER_BODY_ZERO_ANGLES`、`TuyaRobotBase.speed` 调用 SDK `send_upper_angles`，双臂一次下发，单臂仅下发目标臂。
- 约束：已核对当前 SDK 不提供 `send_angles`，实际正式接口名为 `send_upper_angles`；不调用 `upper_go_zero()`，不改变任何测试的门控、恢复时机或超时参数。
- 验证：执行静态编译、CLI 帮助和相关运动模块收集；不运行真机。

## P0：刷新模式角度运动显式启用默认异步

- 状态：已完成（2026-07-29）
- 依据：单臂刷新模式不会同步 SDK 全局默认异步状态；若后续运动调用未传入 `_async`，SDK 会因刷新模式缺少到位反馈而拒绝下发。
- 方案：`send_upper_angle` 的单臂、双臂和软件限位用例在模式回读后调用并验证 `set_upper_motion_async(fresh_mode == 1)`；清理时先切双臂插补模式再回零，最后恢复原左右臂模式和默认异步状态。
- 范围：不新增 Excel 用例、不改变角度目标或真机安全门控。
- 验证：目标模块收集 128 条用例通过；全仓收集受 9 个既有未跟踪测试文件缺少对应 Excel Sheet 阻断，与本方案无关。
