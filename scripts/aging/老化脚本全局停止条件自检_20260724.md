# TuyaRobot 老化脚本全局停止条件自检

## 1. 结论

当前脚本会触发全局停止的主要条件包括：

1. 软件限位运动或关节 Jog 在最终回读时被判定越界；
2. 连续 10 次运动指令超时或空返回；
3. 连续 10 个运动动作未成功；
4. 上半身或底盘机器人状态命中当前支持的错误字段；
5. 上半身或底盘监控连续 3 次发生“非通信类”异常；
6. 运动线程出现未被内部消化的异常；
7. 定时保存报告发生异常；
8. 底盘自动上报初始化发生非 `AgingError`、非 `TimeoutError` 异常。

但是，当前错误检测存在重要缺口：

- 上半身实际返回的 `right.motor_errors`、`left.motor_errors` 无法被当前函数识别；
- 上半身只对 `robot_status` 调用错误判断，没有对已经读取的 `joints_status` 调用；
- 底盘错误识别也只检查固定的顶层字段，若 SDK 返回嵌套结构，同样可能漏报；
- 三组角度、三组坐标和普通目标运动没有实时软件限位保护，通常只会在最终未到位后累计“连续动作失败”；
- 连续通信超时和空返回在监控线程中被定义为可恢复错误，不会因为连续 3 次而停止。

## 2. 直接触发全局停止的条件

### 2.1 上半身软件限位越界

当前只有以下运动明确计算 `exceeded`：

- `send_upper_angle` 单关节正负软件限位；
- `upper_jog_angle` 正负软件限位。

判断规则为：

```text
实际角度 < 软件下限 - 角度容差
或
实际角度 > 软件上限 + 角度容差
```

命中后抛出 `SafetyViolationError`，上半身运动线程外层捕获后调用 `fatal()`。

局限：

- 这是运动结束后的最终回读判断，不是运动过程中的实时保护；
- 三组角度、坐标、增量等动作没有统一计算软件限位越界；
- 如果角度读取超时，动作会按失败记录，不能立即判断越界。

### 2.2 连续运动指令无响应

设备网关把以下接口归类为运动接口：

- `upper_go_zero`；
- `agv_wheel_control`；
- `send_upper_*`；
- `write_upper_*`；
- `upper_jog_*`。

运动接口发生超时或空返回时，连续无响应次数加一。默认达到：

```text
--consecutive-motion-failure-limit 10
```

时抛出 `ConsecutiveMotionFailureError` 并最终触发全局停止。

只要中间有一次运动接口正常响应，连续无响应计数会清零。

### 2.3 连续运动动作未成功

上半身和底盘分别统计连续动作失败，默认连续 `10` 个动作未成功时触发全局停止。

失败包括：

- 未达到目标；
- 运动过程抛出异常后被记录为失败；
- 底盘运动或停止失败；
- 最终到位校验失败。

任意一次运动动作成功会清零对应子系统的连续动作失败次数。

### 2.4 机器人状态命中当前错误字段

上半身当前只检查 `get_upper_robot_status()`，并且只识别：

```text
status
left_arm_error
right_arm_error
```

上述任一字段不是 `0` 或 `None` 时调用：

```text
fatal("上半身", "机器人错误状态", ...)
```

底盘检查机器人状态以及自动上报数据，只识别：

```text
status
left_motor_error
right_motor_error
```

上述任一字段不是 `0` 或 `None` 时触发全局停止。

### 2.5 监控连续非通信异常

默认：

```text
--consecutive-failure-limit 3
```

上半身或底盘监控连续 3 次发生非以下类型异常时触发全局停止：

- `CommunicationResponseError`；
- `EmptyResponseError`；
- `TimeoutError`。

因此，数据类型错误、解析错误、程序逻辑异常等非通信异常连续 3 次会停止。

注意：超时、空返回和 SDK 通信失败属于可恢复异常，即使连续超过 3 次，当前监控代码也不会使用该阈值停止；它们只进入通信错误/丢包统计。

### 2.6 运动线程未处理异常

上半身或底盘运动线程中，任何最终逃逸到线程最外层的异常都会调用 `fatal()`。

但是上半身 `_attempt()` 会把大量普通异常转成一次动作失败，`_phase()` 还会把普通 `AgingError` 和 `TimeoutError` 记录后继续。因此不是所有运动异常都会立即到达线程最外层。

### 2.7 报告保存失败

定时报告线程中 `report.save()` 发生任何异常，立即调用：

```text
fatal("报告", "定时保存", ...)
```

并触发全局停止。

### 2.8 底盘自动上报初始化的非预期异常

底盘自动上报初始化时：

- `AgingError`、`TimeoutError`：记录后重试，不全局停止；
- 其他异常：立即触发全局停止。

由于 `CommunicationResponseError` 和 `EmptyResponseError` 继承 `AgingError`，它们也属于重试路径。

## 3. 不属于“错误全局停止”的正常停止

以下情况也会设置全局 `stop_event`，但不标记为致命错误：

- 达到 `--duration-hours`；
- 达到设定循环次数且请求的运动线程完成；
- `Ctrl+C`、SIGINT、SIGTERM；
- 用户或系统发出中断。

正常完成返回码为 `0`；存在 `fatal_reason` 时返回码为 `1`。

## 4. 当前不会立即停止的错误

### 4.1 单次读取超时或空返回

只记录通信失败、超时或空返回统计，不立即停止。

### 4.2 监控连续通信超时

监控线程将通信超时和空返回视为可恢复错误，目前不会因为连续 3 次触发停止。

### 4.3 单次运动未到位

记录未达到目标点位，累计连续运动失败；默认第 10 个连续失败才停止。

### 4.4 三组角度出现严重偏差

如果没有被明确识别为 `exceeded=True`，即使角度偏差很大，也只算一次未到位。本次右臂最大偏差 `276.43°` 就属于这一类。

### 4.5 当前 SDK 的嵌套电机错误

例如：

```python
{
    "left": 0,
    "right": {
        "motor_errors": [
            {"joint_id": 1, "bitmask": 4096}
        ]
    }
}
```

当前 `upper_status_has_error()` 不识别该结构，不会触发全局停止。

### 4.6 上半身关节状态错误

监控虽然读取 `get_upper_joints_status()`，但只对 `robot_status` 执行错误判断，因此仅出现在 `joints_status` 中的错误不会触发停止。

## 5. 优先级判断

### P0

1. 递归或按 SDK 契约识别 `left/right.motor_errors`；
2. 同时检查 `joints_status` 和 `robot_status`；
3. 明确电机错误、软件限位越界和异常大角度偏差立即停止；
4. 在运动等待过程中实时检查错误和软件限位，不只在运动结束后判断；
5. 底盘状态函数同步兼容真实 SDK 返回结构。

### P1

1. 给监控通信连续失败增加独立停止阈值；
2. 区分“接口有 ACK 但运动失控”和“接口无响应”；
3. 将严重未到位按偏差阈值升级为安全异常；
4. 为每种停止条件增加模拟测试。
