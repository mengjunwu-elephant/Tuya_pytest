# TuyaRobot 老化脚本操作文档

## 1. 文档说明

本文档适用于独立老化脚本：

```text
scripts/aging/tuya_robot_aging.py
```

脚本不依赖 pytest、fixture、`settings.py`、`conftest.py` 或测试 Excel。运行时只创建一个 TuyaRobot 设备连接，并根据命令行开关启动上半身、头部、底盘及监控线程。

> 上半身软件限位、头部软限位、持续 Jog 和底盘运动均为危险实机运动。运行期间必须有人员在现场持续监护，并确保急停装置可立即使用。

### 1.1 程序目录

`tuya_robot_aging.py` 是兼容入口，实际功能按层级放在
`scripts/aging/tuya_aging/`：

```text
tuya_aging/
├── cli.py                 命令行与配置校验
├── config.py              连接和运行参数
├── constants.py           已确认角度、坐标和软件限位
├── domain/                调用结果、运动结果和失败策略
├── device/                唯一连接、通信网关和设备公共动作
├── motion/                上半身、头部和底盘运动流程
├── monitor/               上半身、头部、底盘和自动上报监控
├── report/                日志、统计和 Excel 报告
└── runtime/               线程、停止、恢复和资源协调
```

运行入口和原有命令保持不变。所有真实 SDK 调用统一经过设备网关，
运动和监控层不直接创建或关闭连接。

## 2. 当前功能范围

### 2.0 头部

头部老化为独立子系统，可通过 `--run-head-motion` 单独运行，也可与上半身/底盘并行。

单轮顺序：

```text
上电状态检查（只读）
  → 并行执行（三者各跑一遍、互不等待）：
      · 关节软限位：全关节 send_head_angles 往返 + 单关节 J1～J4 send_head_angle 往返
      · 耳朵 LED：红→绿→蓝→白，各亮 5 秒后恢复关灯
      · 屏幕动画：默认扫描 `tuya_aging/pag_file` 下全部 `.pag` 并逐个播放；目录缺失或无文件则跳过且不致命
  → 三者全部结束后回零 [0,0,0,0]
```

关节运动、LED、动画在同一循环内各自独立起子线程并行执行。所有头部指令经统一网关的头部锁串行化，确保同一 TCP 不会交错发帧；LED 的 5 秒停留只休眠不持锁，动画通过 SSH 上传，均不会长期阻塞关节运动。任一子线程遇到运动越界或连续失败等致命情况时，其余子线程会尽快退出并触发头部局部停止。

已确认头部 1.0 软限位（老化扫边以此为准，不以 SDK ±150 为准）：

| 关节 | 最小° | 最大° | 最大速度°/s（元数据） |
|------|-------|-------|------------------------|
| J1   | -115  | 115   | 150                    |
| J2   | -43   | 28    | 150                    |
| J3   | -43   | 43    | 360                    |
| J4   | -43   | 43    | 360                    |

默认运动速度 `--head-speed` 为 `10`（SDK 1～100 标度）。

遥测（并行 HeadMonitor）：上电、链路使能（只读，不主动开关使能）、角度、错误状态、运行速度、电流、温度。

**局部停机**：头部连续运动失败或监控连续不可恢复失败时，只停止头部运动线程，上半身/底盘继续。全局 `fatal`（如上半身错误）仍会停全部。

耳朵 LED 的 `side` 为位掩码，老化统一使用 `3`（左右耳同时点亮）；`side=0` 固件虽然返回 1，但没有任何一侧生效。

动画文件默认目录：`scripts/aging/tuya_aging/pag_file`。启动时扫描全部 `.pag`，按文件名排序后逐个调用 `play_head_animation(path)`（`intervals_ms`/`play_times_ms` 使用 SDK 默认）；接口立即返回后等待 1 秒再播下一个。单文件失败只记录并继续；目录不存在或无 `.pag` 时跳过动画相位。

动画有两个 SDK 硬性前提：

- 文件名只能是 ASCII 字母、数字、`-`、`_`，且去掉 `.pag` 后不超过 10 个字符；中文名会被 SDK 直接拒绝。
- `play_head_animation` 通过 SSH/SFTP 把 pag 上传到头部树莓派，SSH 参数取自 `~/.tuyarobot/robot_config.yaml` 的 `network` 段，必须包含 `head_ssh_ip`、`head_ssh_port`、`head_ssh_user`、`head_ssh_password` 和 `head_animation_dir`；该段为空时报 `network.head_ssh_ip or network.head_ip is required`。

### 2.1 上半身

上半身老化循环包含：

1. 左右单臂 J1～J7 正、负软件限位运动。
2. `send_upper_angles` 三组角度运动。
3. `send_upper_coords` 三组坐标运动。
4. `write_upper_coords` 别名接口覆盖。
5. 单轴坐标运动接口。
6. 关节 Jog、坐标 Jog。
7. 关节和坐标增量运动。
8. `upper_pause`、`upper_resume`、`upper_stop` 独立控制接口。
9. 角度、坐标、电流、速度、编码器、丢包、关节状态、机器人状态、运动状态和暂停状态监控。

当前暂停刷新模式 `1` 的运动老化，只执行插补模式 `0`。

`send_upper_angles` 的运行顺序为：

```text
回零
  → 左臂连续执行角度组1、组2、组3
  → 回零
  → 右臂连续执行角度组1、组2、组3
  → 回零
  → 双臂连续执行角度组1、组2、组3
  → 回零
```

`send_upper_coords` 的运行顺序为：

```text
进入坐标初始姿态
  → 左臂连续执行坐标组1、组2、组3
  → 回零
  → 进入坐标初始姿态
  → 右臂连续执行坐标组1、组2、组3
  → 回零
  → 进入坐标初始姿态
  → 双臂连续执行坐标组1、组2、组3
  → 回零
```

三组运动中，每组运动结束都会等待停止、读取实际角度或坐标并判断是否到位；只是不在组与组之间执行回零。

### 2.1.1 软件限位、Jog 与单轴坐标回零规则

当前回零顺序如下：

- `send_upper_angle` 软件限位：阶段开始先回零一次；同一手臂同一关节依次执行负软件限位、正软件限位，两个方向都完成后回零，再进入下一个关节。
- `upper_jog_angle`：阶段开始先回零一次；同一目标同一关节依次 Jog 到负、正软件限位，两个方向都完成后回零。正常路径不调用 `upper_stop()`。左/右臂 J2 正向前先将该臂 `send_upper_angle(J1, 50°)` 到位；双臂不执行 J2 正向。
- `upper_jog_angle_increment`：阶段开始先建立一次零位；每个单关节增量动作完成并回读后回零一次，再执行下一个动作。
- `send_upper_coord` 单轴坐标：每个动作前仍进入已确认的双臂坐标初始姿态；24 个单轴动作中间不执行整机回零，全部动作完成后统一回零一次。
- `upper_jog_coord`、三组角度、三组坐标、坐标增量及其他阶段继续使用原有恢复顺序。

按当前插补模式 `0` 的完整流程静态估算，上半身每循环 `go_zero()` 次数由约 219 次降低到约 101 次；正常退出时仍保留协调器的最终恢复回零。

### 2.2 底盘

每个底盘老化循环依次执行：

1. 低速前进。
2. 停止。
3. 同速度后退。
4. 停止。
5. 低速原地正转。
6. 停止。
7. 同速度原地反转。
8. 停止。

底盘监控包含电机电流、速度、温度、编码器、丢包、移动状态、关节状态、机器人状态，以及 100 Hz、20 Hz 自动上报数据。

### 2.3 并行运行

同时指定 `--run-upper-motion`、`--run-head-motion` 和/或 `--run-chassis-motion` 时：

- 各子系统运动线程并行执行。
- 上半身、头部与底盘分别使用独立通信锁。
- 上半身或底盘致命异常会触发全局停止；**头部连续失败只停头部运动**，不牵连其他子系统。
- 报告记录各子系统动作编号与时间；上半身与底盘仍记录并行重叠时长。

## 3. 运行环境

### 3.1 基本要求

- Windows 操作系统。
- 已安装本项目要求的 Python 环境和依赖。
- 上半身网络能够访问机器人 IP 和端口。
- 运行头部时，头部 TCP（默认 `192.168.0.231:6501`）可达。
- 运行底盘时，底盘串口未被其他软件占用。
- 在仓库根目录运行命令：

```powershell
cd C:\Users\HP\Desktop\Tuya_pytest
```

### 3.2 查看命令帮助

```powershell
python scripts\aging\tuya_robot_aging.py --help
```

### 3.3 连接参数

默认连接参数如下：

| 参数 | 默认值 | 环境变量 |
|---|---:|---|
| 上半身 IP | `192.168.0.232` | `TUYA_ROBOT_IP` |
| 上半身端口 | `6500` | `TUYA_ROBOT_PORT` |
| 头部 IP | `192.168.0.231` | `TUYA_HEAD_IP` |
| 头部端口 | `6501` | `TUYA_HEAD_PORT` |
| 底盘串口 | `COM9` | `TUYA_CHASSIS_PORT` |
| 底盘波特率 | `2000000` | `TUYA_CHASSIS_BAUD` |
| SDK 调试日志 | `false` | `TUYA_DEBUG` |
| 直接返回业务数据 | `true` | `TUYA_PLAIN_RETURN` |

命令行参数优先于环境变量。例如：

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-upper-motion `
  --upper-ip 192.168.0.232 `
  --upper-port 6500 `
  --cycle-limit 1
```

运行底盘时可指定串口：

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-chassis-motion `
  --chassis-port COM9 `
  --chassis-baud 2000000 `
  --cycle-limit 1
```

## 4. 运行前检查

每次实机运行前必须完成以下检查：

1. 清理双臂和底盘周围的人员、线缆、工具及其他障碍物。
2. 确认双臂安装状态正常，零位和软件限位配置正确。
3. 确认底盘所在区域能够完成前后移动及原地旋转。
4. 确认急停按钮有效，现场人员能够随时操作。
5. 确认机器人电量、供电和网络稳定。
6. 确认底盘串口未被串口工具或其他测试程序占用。
7. 首次运行先使用一个循环，不要直接执行长时间老化。
8. 不要同时启动其他会连接同一台机器人的测试或调试程序。

## 5. 推荐操作流程

### 5.1 第一步：只校验配置

以下命令不会连接设备，也不会产生运动：

```powershell
python scripts\aging\tuya_robot_aging.py --validate-config
```

输出内容包括：

- 实际使用的连接参数。
- 三组双臂角度。
- 三组双臂坐标。
- J1～J7 软件限位。

确认内容正确后再进行实机运行。

还可以运行无硬件架构验证：

```powershell
python scripts\aging\validate_tuya_aging.py
```

该验证使用模拟对象检查超时/空返回统计、连续十次失败停止、三组运动
顺序、正常 Jog 不调用停止接口、线程选择、并行重叠和报告保存，不连接设备。

### 5.2 第二步：只运行上半身一个循环

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-upper-motion `
  --cycle-limit 1 `
  --debug
```

此模式只会：

- 连接上半身。
- 启动上半身运动线程。
- 启动上半身监控线程。
- 启动报告保存线程。

此模式不会连接底盘，也不会启动底盘读取或自动上报线程。

### 5.2.1 只运行头部一个循环

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-head-motion `
  --cycle-limit 1 `
  --head-speed 10 `
  --debug
```

头部动画默认读取 `scripts\aging\tuya_aging\pag_file\*.pag` 并逐个上传播放；目录缺失或无文件时跳过动画，不致命。

### 5.3 第三步：只运行底盘一个循环

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-chassis-motion `
  --cycle-limit 1 `
  --chassis-forward-mps 0.05 `
  --chassis-rotate-rads 0.1 `
  --chassis-segment-seconds 2 `
  --debug
```

### 5.4 第四步：上半身和底盘并行运行

确认上半身和底盘单独运行都正常后，再执行并行老化：

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-upper-motion `
  --run-chassis-motion `
  --cycle-limit 1 `
  --debug
```

### 5.5 按时间运行

例如运行 8 小时：

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-upper-motion `
  --run-chassis-motion `
  --duration-hours 8 `
  --debug
```

`--duration-hours 0` 表示不限制运行时间。

### 5.6 按循环次数运行

例如每个已启用的运动子系统最多运行 10 个完整循环：

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-upper-motion `
  --run-chassis-motion `
  --cycle-limit 10 `
  --debug
```

`--cycle-limit 0` 表示不限制循环次数。

同时设置运行时间和循环次数时，任意一个结束条件先达到，脚本都会准备退出。

### 5.7 只采集状态

```powershell
python scripts\aging\tuya_robot_aging.py `
  --monitor-only `
  --duration-hours 1 `
  --debug
```

> 注意：`--monitor-only` 当前表示同时监控上半身和底盘，因此会连接底盘并初始化自动上报。如果只想测试上半身，请使用 `--run-upper-motion`，不要使用 `--monitor-only`。

`--monitor-only` 不能与 `--run-upper-motion` 或 `--run-chassis-motion` 同时使用。

## 6. 常用参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `--cycle-limit` | `0` | 最大循环数，0 表示不限次数 |
| `--duration-hours` | `0` | 最大运行小时数，0 表示不限时 |
| `--upper-speed` | `20` | 上半身公共运动速度，范围 1～100 |
| `--jog-speed` | `10` | Jog 速度，范围 1～100 |
| `--upper-timeout` | `60` | 普通上半身运动等待超时，单位秒 |
| `--jog-timeout` | `300` | Jog 到限位等待超时，单位秒 |
| `--monitor-interval` | `0.5` | 状态监控采样间隔，单位秒 |
| `--autosave-interval` | `60` | 报告定时保存间隔，单位秒 |
| `--chassis-forward-mps` | `0.05` | 底盘前后运动速度 |
| `--chassis-rotate-rads` | `0.1` | 底盘原地旋转速度 |
| `--chassis-segment-seconds` | `2` | 每段底盘运动持续时间 |
| `--angle-tolerance` | `0.1` | 上半身角度到位容差，单位度；头部固定使用 `HEAD_ANGLE_TOLERANCE=1.0` |
| `--head-timeout` | `60` | 头部运动等待超时，单位秒；按 `is_head_moving` 结束等待，未到位只记录不追加等待 |
| `--coord-tolerance` | `1.0` | 坐标到位容差 |
| `--consecutive-failure-limit` | `3` | 非通信类监控异常连续出现后触发停止的次数 |
| `--consecutive-motion-failure-limit` | `10` | 连续运动指令无响应或运动未成功的停止阈值 |
| `--auto-report-max-age` | `1.0` | 自动上报允许的最大数据年龄，单位秒 |
| `--report-dir` | `test_report/aging` | 报告根目录 |

自定义报告目录示例：

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-upper-motion `
  --cycle-limit 1 `
  --report-dir "D:\TuyaAgingReports"
```

## 7. 日志说明

每次启动会生成独立运行目录：

```text
test_report/aging/YYYYMMDD_HHMMSS/
```

运行日志文件为：

```text
aging.log
```

日志会记录：

- 每次接口下发的 API 名称、位置参数和关键字参数。
- SDK 原始反馈。
- `result_data()` 解包后的业务数据。
- 每次上半身运动的目标、期望值、实际值、最大偏差、耗时和到位结果。
- 每次底盘运动的速度、旋转速度、持续时间、控制反馈和停止反馈。
- 上半身角度、坐标、电流、速度、编码器、丢包和错误状态。
- 底盘电流、速度、温度、编码器、丢包和错误状态。
- 100 Hz、20 Hz 自动上报内容和数据年龄。
- 接口异常及完整 Python 堆栈。

常见日志格式如下：

```text
上半身接口下发 | api=... | args=... | kwargs=...
上半身接口反馈 | api=... | raw=... | data=...
上半身运动结果 | cycle=... | action=... | expected=... | actual=...
上半身遥测读取 | joint_id=J1 | readings=...
底盘接口下发 | api=... | args=... | kwargs=...
底盘接口反馈 | api=... | raw=... | data=...
底盘遥测读取 | telemetry=...
底盘自动上报读取 | frequency=100Hz | age=... | data=...
```

排查运动问题时，建议按照以下顺序查找同一个动作：

1. 查找“接口下发”，确认 API 和参数。
2. 查找紧随其后的“接口反馈”，确认 SDK 返回值。
3. 查找 `get_upper_is_moving` 反馈，确认运动状态变化。
4. 查找角度或坐标读取反馈。
5. 查找“上半身运动结果”，对比期望、实际和偏差。
6. 如发生全局停止，继续查找“触发全局停止”和异常堆栈。

## 8. Excel 报告说明

每次运行目录主要包含：

```text
summary.xlsx
details_YYYYMMDD_HH.xlsx
aging.log
```

### 8.1 `summary.xlsx`

包含：

- 运行开始时间和累计运行时间。
- 各接口调用数、成功数、失败数和成功率。
- 各接口错误率、超时率、空返回次数和丢包率。
- 运动达到目标点位次数、未达到目标点位次数及连续失败最大次数。
- 最大角度或坐标偏差。
- 软件限位越界次数。
- 电流统计。
- 丢包增量。
- 自动上报样本和延迟统计。
- 上半身与底盘并行运动重叠时间。
- 本次运行配置。

### 8.2 明细报告

`details_YYYYMMDD_HH.xlsx` 按小时轮转，包含：

- `上半身运动`
- `底盘运动`
- `上半身遥测`
- `底盘遥测`
- `自动上报`
- `异常事件`

报告按设定的自动保存周期保存，每个运动循环结束也会保存。

## 9. 正常停止

在运行终端中按：

```text
Ctrl+C
```

脚本收到中断后会：

1. 设置全局停止信号。
2. 停止底盘。
3. 对上半身执行退出清理。
4. 等待线程退出。
5. 正常状态下尝试回零。
6. 恢复原始运动模式和自动上报状态。
7. 保存最终报告。
8. 关闭唯一设备连接。

不要直接关闭 PowerShell 窗口或强制结束 Python 进程，否则清理、模式恢复和最终报告保存可能来不及执行。

## 10. 异常停止策略

出现以下情况之一时，脚本可能触发全局停止：

- 连续运动指令无响应达到设定阈值，默认 10 次。
- 连续运动动作未成功达到设定阈值，默认 10 次。
- 软件限位越界。
- 上半身或底盘报告错误状态。
- 非通信类监控异常连续达到设定次数。
- 报告保存失败。

单次接口超时、查询空返回、普通运动/Jog 超时以及单次角度或坐标未到位只记录，不立即触发全局停止。通信读取会累计调用、成功、失败、超时、空返回和丢包率；运动会累计达到目标点位与未达到目标点位次数。

致命异常发生后：

- 会通知另一个运动子系统停止。
- 底盘会执行停止。
- 必要时上半身执行急停。
- 错误状态下不强制执行回零。
- 最终错误会记录到 `aging.log` 和 Excel 的“异常事件”工作表。

## 11. 常见问题排查

### 11.1 只运行上半身，却出现底盘读取超时

正确命令：

```powershell
python scripts\aging\tuya_robot_aging.py --run-upper-motion --cycle-limit 1
```

不要附加 `--monitor-only` 或 `--run-chassis-motion`。当前脚本只在指定底盘运动或仅监控模式时连接底盘并启动底盘监控线程。

### 11.2 `get_agv_auto_report timeout`

错误示例：

```text
TuyaRobot 命令执行失败:
{"status_code": 0, "message": "get_agv_auto_report timeout"}
```

检查：

1. 是否误用了 `--monitor-only`。
2. 底盘串口号是否正确。
3. 波特率是否为设备当前配置。
4. 串口是否被其他程序占用。
5. 底盘是否上电并完成初始化。
6. USB 转串口连接是否稳定。

如果本次只需要上半身，退出后改用 `--run-upper-motion`。

### 11.3 下发运动后实际角度仍为 0

在 `aging.log` 中依次检查：

1. `send_upper_angle` 或 `send_upper_angles` 下发参数。
2. SDK 原始反馈是否表示命令接收成功。
3. `get_upper_is_moving` 是否出现运动状态。
4. 最终 `get_upper_angles` 返回值。
5. 关节状态和机器人错误状态。

如果控制器始终未进入运动状态，重点检查：

- 目标臂是否上电。
- 是否存在未清除错误。
- 当前运动模式是否正确。
- 目标角度是否被控制器拒绝。
- 是否存在碰撞、限位或使能状态异常。

不要仅通过延长等待时间掩盖控制器未执行运动的问题。

### 11.4 日志文件过大

当前脚本按排障需求记录每一次接口调用和读取内容，长时间运行会产生较大的 `aging.log`。

可适当增大监控间隔，例如：

```powershell
python scripts\aging\tuya_robot_aging.py `
  --run-upper-motion `
  --monitor-interval 2 `
  --duration-hours 8
```

这只会降低遥测采样频率，不改变运动等待过程中的状态查询。

### 11.5 报告无法保存

检查：

- 报告目录是否有写入权限。
- Excel 文件是否被人工打开并锁定。
- 磁盘空间是否足够。
- 杀毒软件是否阻止临时文件替换。

运行期间尽量不要直接打开当前小时的明细 Excel。需要查看时，先复制文件副本。

## 12. 首次实机运行建议

推荐按以下顺序逐步放开：

1. 执行 `--validate-config`。
2. 确认机器人周围安全。
3. 上半身单独运行一个循环。
4. 检查 `aging.log`、角度反馈和异常事件。
5. 底盘单独运行一个循环。
6. 检查底盘自动上报、丢包和停止结果。
7. 上半身和底盘并行运行一个循环。
8. 确认并行运动稳定后，再设置长时间或多循环老化。

任何异常都应先保留完整运行目录，再重启设备或重新执行，以免丢失现场日志。
