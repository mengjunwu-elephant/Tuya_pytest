# TuyaRobot 老化脚本自检与回零优化方案

更新日期：2026-07-23

> 实施状态更新：用户已确认并完成第一批回零编排调整。软件限位和关节 Jog 均改为同一关节负、正限位完成后回零；关节增量每动作完成后回零一次；单轴坐标整批完成后统一回零。其他阶段保持原设计。当前完整循环静态估算约 `101` 次 `go_zero()`。本文后续 `219` 次数据为调整前审计基线。

## 1. 审计范围与结论

本次只进行静态审计和本机 SDK 契约核对，没有连接真实硬件，也没有修改运动代码。

审计范围：

- `scripts/aging/tuya_aging/` 分层老化包。
- 上半身所有运动阶段、等待逻辑、失败策略和状态监控。
- 底盘运动、自动上报、线程退出和连接关闭。
- 仓库 `AGENTS.md`、`.cursorrules`、运动技能和运动测试计划。
- 本机已安装 `pytuyarobot` 的真实接口签名与状态解码函数。

核心结论：

1. 调整前每个完整上半身老化循环静态估算会调用约 `219` 次 `go_zero()`，正常退出时协调器还会再回零一次。
2. 其中约一半属于“上一动作刚回零，下一动作又先回零”或“回零后马上进入坐标初始姿态”的重复机械往返。
3. 不能直接批量删除回零。当前存在“运动超时后未确认停止就继续下一动作”等高优先级安全风险，必须先解决未知姿态问题。
4. 用户确认的软件限位与关节 Jog 改为正负方向完成后回零，实际调整后每循环约为 `101` 次。

## 2. 风险分级

### P0：真机继续老化前应优先修复

#### P0-1 运动异常后可能在未知运动状态下继续下发下一动作

位置：

- `motion/upper_runner.py::_attempt()`
- `device/upper_body.py::wait_until_stopped()`

当前单次发送超时、状态读取超时、等待运动停止超时或未到位会被记录，然后继续后续动作。除坐标阻塞 Jog 外，普通角度、坐标和增量运动异常时不会先确认设备已经停止。

风险场景：

- 软件下限指令实际已经执行，但 ACK 或状态读取超时。
- 脚本记录失败后立即发送同关节软件上限。
- 前一运动仍在进行，后一运动覆盖或叠加，实际姿态不可控。

建议：

- “记录并继续”应解释为“不触发全局退出”，不能解释为“立即下发下一运动”。
- 单次运动失败后进入局部恢复状态：
  1. 短时重读运动状态和角度/坐标。
  2. 能确认停止且姿态可信时继续。
  3. 无法确认停止时执行一次 `upper_stop()`，仅作为异常恢复。
  4. 停止后回到该阶段要求的基准姿态，再执行下一动作。
- 以上恢复失败才累计为一个完整运动动作失败；连续达到阈值后全局停止。

#### P0-2 双臂错误状态识别会漏报

位置：

- `utils.py::upper_status_has_error()`
- `monitor/upper_monitor.py`

本机 SDK 的 `get_upper_robot_status()` 返回结构为：

```python
{
    "left": 0或{"soft_error": ..., "motor_errors": ...},
    "right": 0或{"soft_error": ..., "motor_errors": ...},
}
```

当前实现只检查顶层 `status`、`left_arm_error` 和 `right_arm_error`，因此 SDK 返回左右臂嵌套错误时可能始终判断为无错误。

建议：

- 按 SDK 当前真实结构判断 `left`、`right` 是否为 `0`。
- 同时兼容旧结构，但不要只检查旧结构。
- 对 `get_upper_joints_status()` 的错误位也应建立明确解释和致命错误规则，不能只记录原始数据。

#### P0-3 坐标初始姿态把夹爪速度传成了 50

位置：

- `device/upper_body.py::move_to_coord_initial_pose()`

本机 SDK 已确认签名：

```python
send_upper_angles(
    left_angles,
    left_arm_speed,
    left_gripper_speed,
    right_angles,
    right_arm_speed,
    right_gripper_speed,
)
```

当前双臂调用把 `constants.SPEED=50` 同时作为手臂速度和夹爪速度；单臂调用也显式传入了第三个参数 `50`。原老化方案要求夹爪速度固定为 `0`。

建议：

- 双臂坐标初始姿态使用 `50, 0, 50, 0`。
- 单臂调用省略夹爪速度或显式传 `0`。
- 恢复速度建议与公共恢复速度 `20` 分离命名，避免一个 `SPEED` 同时表示运动速度和夹爪速度。

### P1：影响安全策略准确性和长期稳定性

#### P1-1 连续“运动指令无响应”可能被回零成功打断

`upper_go_zero` 被网关归类为运动接口。测试运动无响应后，如果恢复回零 ACK 成功，会清零“连续运动指令无响应”计数。这样可能出现被测运动接口长期无响应，但始终达不到连续 10 次停止阈值。

建议把计数拆成：

- 被测运动指令连续无响应。
- 恢复指令连续无响应。
- 完整运动动作连续失败。

恢复命令不应清零被测接口无响应计数；被测运动成功才清零。

#### P1-2 阶段前置动作失败没有统一计入动作失败阈值

`go_zero()`、坐标初始姿态和模式设置在 `_attempt()` 外执行。它们失败时阶段被跳过，但不一定增加“连续运动动作失败”计数。设备长期不可用时可能无限循环阶段，而不是在阈值后停止。

建议将阶段前置恢复也建模为动作结果，或单独增加连续恢复失败阈值。

#### P1-3 移动状态启动宽限只有 1 秒

`wait_until_stopped()` 在 1 秒内没有观察到移动状态，就把连续静止视为动作结束。如果控制器启动延迟超过 1 秒，可能过早回读角度并判定未到位，然后继续下一动作。

建议：

- 运动 ACK 后同时观察“移动状态变化”和“目标反馈变化”。
- 未观察到启动时，不应仅凭固定 1 秒判定动作完成。
- 对不同速度和大范围软件限位设置不同启动确认窗口。

#### P1-4 坐标增量在左右臂切换时留下未经确认的组合姿态

当前坐标增量中间已经不回零，这是正确的减负方向；每个动作前仍把目标臂恢复到坐标初始姿态。

但左臂最后一个 `RZ +30°` 完成后，进入右臂阶段时只移动右臂到初始姿态，左臂会停留在偏移姿态。这个“左臂偏移 + 右臂坐标增量”的组合姿态没有明确实机确认。

建议：

- 同一手臂内部不回零。
- 左臂组结束后，把左臂恢复到坐标初始姿态。
- 右臂组结束后，把右臂恢复到坐标初始姿态。
- 进入双臂 Z 增量前，把双臂统一恢复到坐标初始姿态。
- 全部坐标增量结束后只回零一次。

这里需要的是“组间坐标基准恢复”，不是频繁整机回零。

#### P1-5 监控查询负载可能放大通信超时

上半身监控默认每 `0.5` 秒串行读取约 10 个接口；运动等待同时每 `0.1` 秒读取移动状态。虽然网关使用同一上半身锁避免同时发帧，但请求密度高，可能延迟运动状态查询、制造超时并放大日志量。

建议：

- 运动期间只保留移动状态、错误状态和关键电流高频采样。
- 角度、坐标、编码器、速度和逐关节丢包改为轮转低频采样。
- 将遥测快照标记采样起止时间，避免把分时数据误当同一时刻状态。

#### P1-6 线程等待 10 秒后可能在工作线程未退出时恢复并关闭连接

协调器对每个线程只 `join(timeout=10)`，之后无论线程是否仍存活，都会执行模式恢复、回零和关闭连接。阻塞坐标 Jog 或底层 SDK 线程没有退出时，可能出现恢复命令与旧线程并发，或者线程继续访问已关闭连接。

建议：

- join 后检查 `thread.is_alive()`。
- 工作线程未退出时不要执行正常回零。
- 记录未退出线程并进入明确的强制停止/连接关闭策略。
- 阻塞 Jog 必须确认后台调用线程结束，不能只清理外层 Runner。

### P2：统计和可维护性风险

#### P2-1 全向量未到位时会丢失实际反馈和最大偏差

`assert_dual_vectors()` 在偏差超容差时直接抛异常，`_attempt()` 最终记录的 `actual` 为空、`error=None`。报告能累计未到位次数，但无法保留当时的真实角度/坐标和最大偏差。

建议把“计算偏差”和“决定是否通过”分开，始终返回实际反馈。

#### P2-2 回零容差与 CLI 角度容差不一致

回零固定使用 `constants.ANGLE_TOLERANCE=1.0°`，软件限位和普通角度默认使用 CLI 的 `0.1°`。这会让回零最多偏差 1°仍被视为成功。

建议回零使用统一的 `options.angle_tolerance`，或者单独提供明确的 `--zero-angle-tolerance`。

#### P2-3 上半身运动开关会一次执行全部危险阶段

当前只有 `--run-upper-motion` 总开关，启用后会依次执行软件限位、全角度、全坐标、关节 Jog、坐标 Jog 和暂停恢复，没有阶段选择、断点续跑或单接口调试开关。

建议增加：

- `--upper-phases`
- `--start-phase`
- `--skip-phases`

默认仍可保持完整老化，但现场排错时不必重复执行前面的危险动作。

#### P2-4 日志仍然偏高频

虽然 `get_upper_is_moving` 正常日志已静默，但监控每次会打印完整遥测，同时网关会打印其他每个查询的下发和反馈。长时间运行可能产生较大日志和磁盘 I/O。

建议把普通遥测接口成功日志降为 `DEBUG`，INFO 只保留周期摘要、运动结果和异常。

## 4. 哪些回零必须保留

### 必须高频保留

1. **关节 Jog 到软件限位**
   - 每个方向必须从零位或同等经过确认的安全基准姿态开始。
   - 正负方向之间必须恢复一次。
   - 可以去掉重复的“上一动作结束回零 + 下一动作开始回零”，但不能取消动作间基准恢复。

2. **关节增量**
   - 当前期望值直接按从零位增量计算，每个关节动作必须从零位开始。
   - 同样只需要动作之间一次回零，不需要前后各一次。

3. **坐标 Jog 到状态码 32**
   - 结束位置在工作空间边界附近，而且不是固定软件限位。
   - 在没有验证安全返回轨迹前，建议保留每个动作结束后的回零。
   - 这是当前最不适合为了减少次数而直接删回零的阶段。

4. **软件限位**
   - 每个关节完成负限位和正限位后必须回零，再测试下一个关节。
   - 每个关节开始前如果已经确认处于零位，则不需要再重复回零。

5. **正常退出**
   - 正常完成、定时结束和人工中断后保留最终回零。
   - 致命错误状态下不强制回零。

### 可以合并或替换

1. **单关节软件限位**
   - 当前每关节前后各一次。
   - 改为阶段开始一次，每关节结束一次。
   - 约从 28 次降到 15 次。

2. **三组关节角度**
   - 每个 target 的三组结束后回零即可。
   - 去掉 target 开始前与上一 target 结束后重复的回零。
   - 约从 6 次降到 3 次。

3. **`write_upper_coords` 三组**
   - 与 `send_upper_coords` 一样连续执行三组后统一回零。
   - 约从 3 次降到 1 次。

4. **单轴坐标**
   - 每个动作前已经调用双臂坐标初始姿态。
   - 中间无需再执行“动作结束回零 → 下一动作又去坐标初始姿态”。
   - 建议同一批动作只在最后回零一次。
   - 约从 24 次降到 1 次。

5. **关节 Jog**
   - 阶段开始回零一次，每动作完成后回零一次。
   - 下一动作开始前不重复回零。
   - 约从 84 次降到 43 次。

6. **关节增量**
   - 阶段开始回零一次，每动作完成后回零一次。
   - 约从 42 次降到 22 次。

7. **坐标增量**
   - 保持当前全部结束后只回零一次。
   - 增加左右臂组间的坐标初始姿态恢复，不增加整机回零。

8. **协调器正常退出**
   - 如果最后一个动作已经完成回零并通过回读，可以跳过重复回零。
   - 应使用“已确认零位”状态判断，不能简单删除兜底恢复。

## 5. 推荐实施优先级

### 第一优先级：先保证未知状态不继续运动

1. 修复运动异常后的局部停止、状态确认和基准恢复。
2. 修复双臂错误状态嵌套识别。
3. 修复坐标初始姿态夹爪速度为 `0`。
4. 增加阻塞线程退出确认。

### 第二优先级：修正失败统计

1. 分离被测运动、恢复运动和完整动作失败计数。
2. 前置恢复失败纳入连续失败策略。
3. 未到位时保留真实反馈和偏差。

### 第三优先级：回零去重

1. 先处理确定重复的关节限位、关节 Jog 和关节增量。
2. 再合并三组角度、三组坐标和单轴坐标的恢复动作。
3. 坐标 Jog 暂时保留每动作回零。
4. 坐标增量只增加组间坐标基准恢复，不恢复高频整机回零。

### 第四优先级：降低通信和日志负载

1. 运动期间遥测分级、轮转采样。
2. 普通查询成功日志降为 DEBUG。
3. 增加阶段选择和断点续跑参数。

## 6. 预期优化结果

保守估算：

- 当前：约 `219` 次 `go_zero()` / 完整上半身循环。
- 用户确认的第一批调整后：约 `101` 次 / 循环。
- 相对调整前降幅：约 `54%`。

此估算保留了坐标 Jog 每动作回零，因此没有用减少次数换取未知边界姿态风险。

## 7. 验证要求

不连接硬件的验证：

- 静态验证每阶段回零次数。
- 模拟动作失败后不会立即下发下一运动。
- 模拟第 1～9 次被测运动无响应继续，第 10 次停止，恢复回零不能清零该计数。
- 模拟嵌套左右臂错误状态立即触发全局停止。
- 验证坐标初始姿态的左右夹爪速度均为 `0`。
- 验证坐标增量左右臂切换时先恢复对应坐标基准。
- 验证线程未退出时不会关闭连接或执行正常回零。

真机验证必须人工监护并分阶段执行：

1. 仅验证坐标初始姿态和夹爪不动作。
2. 仅验证一个普通小幅角度动作的超时恢复。
3. 仅验证一个关节正负 Jog 的单次恢复链路。
4. 最后才运行完整循环。
